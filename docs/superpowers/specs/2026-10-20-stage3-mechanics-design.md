# Stage 3: механика, которая чувствуется. Дизайн

Дата: 2026-10-20. Основа: ТЗ v0.1, фидбэк после первой игровой недели, аудит движка (`ecc:code-explorer`, 2026-10-20).

## 0. Зачем

Фидбэк игрока после первой недели:
1. **Дни однообразные.** Швартовки и якорь каждый день одни и те же. Условия не меняются, поэтому повторяешь прошлое решение. Ветер не приходит с разных сторон.
2. **Главное: очки на старте ни на что заметно не влияют.** Выбор лодки тоже: вода не кончается, аккумулятор не садится, ничего не ломается.
3. **Хочется роста по ходу недели.** Ошибка стоит денег или повреждения, но даёт опыт, и дальше становится безопаснее.

Дополнительная цель от пользователя: **масштабируемость контента.** Новые лодки, поломки, манёвры, события, погода и районы добавляются данными, без кода. Тогда игроку интересно повторять неделю, а мы можем выпускать новый контент.

## 1. Что показал аудит (почему так)

| Наблюдение | Причина в коде |
|---|---|
| Манёвры не меняются | Ровно 4 манёвра (`content/maneuvers.json`). Порядок шагов фиксирован. Выбор зависит только от типа точки (`day/passage.ts:113`, `day/arrival.ts:51-56`). Ветер, грунт и марина не влияют на правильный ответ. |
| Ветер всегда с одной стороны | Один шаблон погоды `meltemi_week`, направление всегда NW. Прогноз детерминирован, случаен только фронт (`weather.ts:14-34`). |
| Голоса не видны | Эффект Осторожности и Порядка спрятан в множителе риска (`voices.ts:54-58`) и нигде не показан. Механик даёт только точные цифры (`voices.ts:49-52`). У Экономиста, Гордости и Голоса экипажа механики нет. Все реплики требуют уровень ≤ 2, у уровней 3–4 реплик нет. Разбор голоса не упоминает. |

| Нет роста | Голоса задаются один раз в `setup.ts:40-45` и больше не меняются. |
| Прочее | 30 событий, все одноразовые. События в пути бросаются после дня по месту прибытия, а не по маршруту. Грунт в UI не показан. В текстах событий есть несуществующие члены экипажа (Света, Денис). |

## 3. Контентный фундамент

### 3.1 Контент-паки

```
content/
  core/                   общее для всех районов
    balance.json
    boats.json
    systems.json          (новое)
    maneuvers.json
    crew.json             пул архетипов экипажа
    briefing.json
    dialogues.json
    debrief.json
  regions/
    archipelago/
      region.json         карта, точки, маршруты (бывшие map.json и routes.json)
      weather/*.json      шаблоны недели (несколько)
      events.json         события района (плюс core-события, если появятся)
```

- Загрузчик (`src/ui/content.ts` плюс `validate`) собирает `Content` из `core` и выбранного района.
- Меню выбирает район. Пока он один, выбор скрыт. Шаблон погоды, экипаж и дефекты лодки выбираются по seed.
- Тип `Content` получает поле `region: RegionId`. Сохранение хранит id района.

### 3.2 Условия

Существующий `expr.ts` остаётся единым языком условий. Новые ключи:

| Ключ | Значение |
|---|---|
| `wind.kn`, `wind.dir` | ветер в момент проверки |
| `wind.side` | `bow`/`stern`/`port`/`starboard`/`none`: ветер относительно причала, только в обстановке манёвра |
| `place.marinero`, `place.seabed`, `place.tight`, `place.berth` | обстановка (§6.2) |
| `system.<id>.state`, `system.<id>.broken` | состояние систем (§5.1) |
| `voice.<id>` | уже есть, распространяется на все места |
| `leg.feature.<f>` | признаки текущего перехода: strait, cape, open, gulf |

Валидатор проверяет, что каждый ключ, используемый в контенте, известен движку.

### 3.3 Шансы с разбивкой

Единый формат любого броска (событие, отказ системы, ошибка манёвра, якорь, отказ марины, починка):

```json
"chance": {
  "base": 0.18,
  "mods": [
    { "if": "checkin.impeller", "add": -0.10, "label": "checkin" },
    { "voice": "mechanic", "perLevel": -0.03 },
    { "if": "system.engine_cooling.state == 'worn'", "add": 0.08, "label": "worn" }
  ],
  "min": 0.02, "max": 0.9
}
```

- Короткая форма `"chance": 0.3` остаётся и означает `{ base: 0.3 }`. Совместимо со старым контентом.
- `evaluateChance(spec, ctx) → { value, parts: [{ source, delta }] }`. Это чистая функция. Те же `parts` уходят в UI и в журнал.
- Существующие правила переводятся на этот формат без изменения чисел: проверка голоса (`checks.base/perLevel`, усталость), множитель риска Осторожности и Порядка, отказ якоря (грунт, ветер, ночь, брифинг), отказ марины.
- Каждый бросок пишет в журнал `cause` и `parts`, из них потом считается блок разбора «Голоса недели» (§4.4).

### 3.4 Эффекты

`Effect` получает новые поля:
- `xp: { [voice]: number }`;
- `repair: SystemId`;
- `wear: { [system]: number }`;
- `break: SystemId`.

Мёртвый `repair` из текущего кода заменяется настоящим.

### 3.5 Опыт как данные

- Ошибка манёвра, вариант события, проверка или отказ системы могут объявить `xp`.
- По умолчанию: проверка голоса V даёт `xp.V +1` за успех и `+3` за провал. Ошибка манёвра даёт `order +3`. Манёвр без ошибок даёт `order +1`, но не чаще одного раза за день. С 3c это правило работает только в обстановке, где набор шагов отличается от прошлого манёвра того же типа, чтобы заученный ответ не фармил опыт.
- Пороги в `balance.json`: `voices.xpToLevel: [6, 10, 15, 21]` (0→1, 1→2, 2→3, 3→4).
- `pride`, `crew_voice` и `economist` опыта не получают: `voices.xpExempt`.

### 3.6 Инструменты контентщика

**`npm run validate`** (расширение существующего):
- схемы zod и ссылочная целостность (уже есть);
- **поиск мёртвого контента**:
  - флаг пишется, но не читается, и наоборот;
  - событие с условием, которое никогда не выполнится при данных района (статическая проверка ключей и диапазонов);
  - система без режимов отказа;
  - дефект без системы;
  - тема брифинга или чек-поинт, на которые ничто не ссылается;
- шансы в [0, 1]; каждый `voice` в `mods` и `xp` существует.

**`npm run sim -- --weeks 500 [--boat X] [--strategy S]`**:
- прогоняет недели ботом без UI через публичное API движка;
- стратегии: `careful`, `reckless`, `ignore-weakness` (игнорирует слабость лодки), `random`;
- отчёт (markdown и json):
  - частота каждого события;
  - дни, когда кончается каждый ресурс, по лодкам;
  - отказы систем;
  - рост уровней за неделю;
  - шанс травмы;
  - итоговые оценки.

## 4. Голоса: видимые и растущие (план 3a)

### 4.1 Шансы на виду

Каждый шанс показывается там, где принимается решение. По тапу раскрывается разбивка.
- Варианты событий: `[Механик · 65%]`, раскрытие показывает «база 50% · Механик 3 +15% · усталость −5%».
- Приказы на манёвр: «если ошибёшься — риск травмы 12% (Осторожность 2 −16%, Порядок 1 −10%)».
- Превью плана: риск отказа парусов на переходе, шанс отказа марины при этом времени прихода, шанс неудачи с якорем (с грунтом).

### 4.2 Работа каждого голоса

На экране создания капитана каждый голос показывает таблицу «что даёт уровень» с числами из `balance.json`.

| Голос | Эффект |
|---|---|
| Морское чутьё | Ур. 2: местное усиление и сигналы фронта (есть). **Ур. 3: шанс фронта на день числом. Ур. 4: час прихода фронта.** |
| Осторожность | Ниже риск травм и поломок, дольше манёвры (есть, теперь видно). |
| Порядок | Ниже риск травм, проверки (есть). **Ур. 3+: подсказывает один шаг манёвра, зависящий от обстановки.** |
| Механик | Точные цифры с ур. 2 (есть). **Ниже шанс отказа систем, выше шанс починки (3b).** |
| Дипломат | Мягче сорванные обещания (есть). **Проверки с маринеро и соседями, торг за место в марине.** |
| Экономист | **−5% за уровень на марину, топливо и таверну.** Реплики тянут в бухты: ложный голос, иногда прав. |
| Гордость | Без изменений: фиксированный уровень 2, ложный голос. |
| Голос экипажа | **Реплики по условиям настроения** (`mood`), «отражает настроение» по ТЗ. |

Контент: реплики с `min_level` 3 и 4 для 5 прокачиваемых голосов, по 2 и более на голос. Реплики уровня 3–4 точнее (с цифрами), а не просто громче.

### 4.3 Рост

- В `GameState` появляется `voiceXp: Record<TrainableVoice, number>`.
- Опыт начисляется в момент причины. **Уровень растёт вечером** (фаза evening), один раз за день. Внутри дня шансы не меняются.
- Экран вечера и журнал показывают: «⬆ Порядок 2 → 3» и причины («кормовые отданы раньше брифинга, +3»).
- Потолок `maxLevel` 4. Лишний опыт на уровне 4 не копится.

### 4.4 Голоса в разборе

Новый блок «Голоса недели», считается из журнала:
- уровень на старте и в конце, опыт по источникам;
- что голос изменил, по сумме `parts`:
  - «Осторожность: 3 ошибки манёвра, риск травмы снижен на 4 п.п. каждая»;
  - «Экономист: сэкономил 64 €»;
  - «Чутьё: предупредило о фронте в среду».

### 4.5 Критерии готовности 3a

- [ ] Каждый бросок в движке идёт через `evaluateChance`, ни одного «голого» `chance(rng, p)` с числом из кода. Проверяется тестом-грепом.
- [ ] UI показывает разбивку у вариантов событий, приказов манёвра и превью.
- [ ] Опыт и рост уровня работают и видны вечером и в журнале. Бот недели видит хотя бы один рост.
  Итог 3a: бот-новичок растёт (до +4), бот-эксперт часто не растёт, потому что опыт идёт в основном за ошибки. Решение пользователя от 2026-10-20: кривую опыта настраивать в 3b, вместе с поломками (см. 5.6).
- [ ] У Экономиста и Голоса экипажа есть механика. У уровней 3–4 есть реплики.
- [ ] Блок «Голоса недели» в разборе.
- [ ] `validate` ловит мёртвый контент. Текущий мёртвый контент удалён или подключён.
- [ ] `npm run sim` работает и стоит в CI (100 недель).
- [ ] Контент переехал в `core/` и `regions/archipelago/`. Слот сохранения `v2`.

## 5. Лодка ощутимая (план 3b)

### 5.1 Системы

Новый файл `core/systems.json`. Стартовый набор систем: `engine_cooling`, `heads`, `windlass`, `electrical`, `rig` (паруса и такелаж), `gas`, `bow_thruster`.

```json
{
  "id": "engine_cooling",
  "name": { "ru": "Охлаждение двигателя", "en": "Engine cooling" },
  "checkpoint": "impeller",
  "failures": [{
    "id": "impeller_overheat",
    "phase": "passage",
    "when": "leg.motor_hours > 0",
    "chance": { "base": 0.04, "mods": [
      { "if": "system.engine_cooling.state == 'worn'", "add": 0.14, "label": "worn" },
      { "perWear": 0.01 },
      { "voice": "mechanic", "perLevel": -0.02 } ] },
    "effect": { "break": "engine_cooling", "time_hours": 0.5 },
    "brokenEffect": { "motor": false },
    "xp": { "mechanic": 3 }
  }],
  "wearPer": { "motor_hour": 1 },
  "repairs": [
    { "id": "self", "check": { "voice": "mechanic", "difficulty": 2 }, "costEur": 40, "timeHours": 1, "needs": "spare.impeller" },
    { "id": "service", "where": "marina", "costEur": 220, "timeHours": 3 },
    { "id": "live_with", "dailyEffect": { "mood": -2 } }
  ]
}
```

- `GameState.systems: Record<SystemId, { state: 'new'|'ok'|'worn', wear: number, broken: boolean }>`.
- Сломанная система применяет `brokenEffect`, который движок понимает:
  - нет мотора: только паруса, на якорь и швартовку штраф;
  - нет гальюна: настроение каждый день;
  - нет лебёдки: якорь вручную, +время и +усталость;
  - нет подрульки: нет бонуса.
- Ремонт — это действие игрока: событие-выбор в момент отказа и пункт «Ремонт» на экране вечера.
- Существующие события поломок (`impeller_overheat`, `toilet_clog`, `toilet_misuse`, `gas_smell`, `genoa_seam_rip`, `anchor_shackle_loose`) становятся режимами отказа систем. Их тексты и проверки сохраняются.

### 5.2 Лодка как профиль систем

`boats.json` получает поля:
- `systems: { [id]: 'new'|'ok'|'worn' }`;
- `defectPool: [{ id, system, checkpoint, effect }]`;
- `defectsPerWeek: [2, 3]`.

Дефекты на неделю выбираются по seed. Найденный на чек-ине дефект даёт выбор:
- **чинить на базе**: деньги и время из бюджета, система становится `ok`;
- **плыть так**: система `worn`, шанс отказа выше.

Бюджет чек-ина в `balance.checkin.budgetMin` ужимается так, чтобы проверить всё было нельзя. Точное число подбирается симулятором, ориентир — 60% от суммы стоимостей.

### 5.3 Слабость каждой лодки

| Лодка | Блестящее (ловушка) | Слабость |
|---|---|---|
| Аврора 45 | подрулька, плоттер, электрогальюны | Общий банк: к третьей ночи на якоре садится аккумулятор. Подрулька `worn`, может отказать при боковом ветре. |
| Мельтеми 40 | почти ничего | `rig: worn`: отказы парусов при ветре от 18 узлов. Тихоходная: позже приходит, места в марине заняты. Аккумулятор остаётся сильной стороной. |
| Калипсо 38 | стерео, тик | Маленькие танки. Вода без марины кончается за 3 дня (normal), топливо за 4 дня на моторе. |

Баланс подбирается через `npm run sim --strategy ignore-weakness`: слабость лодки бьёт в ≥ 60% недель.

### 5.4 Цена ошибок

- **Пустой бак:** если ветер ниже `minSailWindKn`, вызывается буксир (`rescue.towEur`, время, настроение). Иначе только паруса, плюс запись в журнале.
- **Деньги в оценке:** у оценки недели появляется ось «бюджет». Учитываются потерянный депозит, перерасход относительно стартового остатка и платный ремонт.
- **Отрицательный баланс:** марина и таверна недоступны с причиной «нет денег», экипаж без ужина в ресторане.

### 5.5 Мёртвые поля

- `bowThruster` становится системой `bow_thruster`: при боковом ветре снижает шанс ошибок швартовки, но может отказать.
- `generator` удаляется.
- `toilet_valve` переходит в пул дефектов `heads`.
- Чек-поинт `electrics` относится к системе `electrical`.
- Тема брифинга `sails` ссылается на отказы `rig` (смягчение).

### 5.6 Критерии готовности 3b

- [ ] Системы с отказами, износом и ремонтом. Механик видимо влияет на шанс отказа и починки.
- [ ] Дефекты выбираются из пула по seed. Чек-ин даёт выбор «чинить или плыть».
- [ ] Симулятор подтверждает слабость каждой лодки (≥ 60% при `ignore-weakness`) и что каждая лодка проходима при `careful`.
- [ ] Деньги в оценке. Пустой бак и отрицательный баланс имеют последствия.
- [ ] Старые события поломок переехали в системы без потери текстов.
- [ ] Кривая опыта перенастроена (перенесено из 3a). Осторожная игра тоже даёт рост: симулятор показывает хотя бы один рост у `expert` за неделю. Частота травм у `newbie` пересмотрена: в 3a было 0.99 за неделю.

## 6. Разнообразие дней (план 3c)

### 6.1 Шаблоны погоды

- `regions/archipelago/weather/` содержит 4 шаблона: `meltemi` (NW, крепчает), `calm_then_front`, `sirocco` (S–SE, волна), `variable`.
- Шаблон задаёт по дням базовое направление, диапазон силы и шансы фронта, плюс джиттер `±1` румб и `±2` узла (по seed).
- Направление ветра дня определяет:
  - курс к ветру на переходах (уже есть, теперь варьируется);
  - **укрытость бухт:** на карте у точки значок «укрыта / открыта» под ветер дня, на основе существующего `shelter`;
  - **сторону ветра на швартовке.**

### 6.2 Обстановка на подходе

Перед приказами движок строит `Situation` (детерминированно по seed):

```ts
interface Situation {
  berth: 'stern_to' | 'side_to' | 'anchor' | 'anchor_ashore';
  windSide: 'bow' | 'stern' | 'port' | 'starboard' | 'none';  // из ориентации причала и ветра
  windKn: number;
  marinero: boolean;          // шанс у места, падает к вечеру
  seabed: Seabed;
  tight: boolean;             // теснота / сосед
}
```

- Точки в `region.json` получают `berths: [{ type, headingDeg }]` и `marineroChance`.
- Игрок видит карточку «Обстановка» на экране приказов. Для марины и набережной она строится по прогнозу на час прихода. Факт может отличаться: ветер реальный, маринеро бросается при прибытии. Карточка честно помечает, что прогноз, а что факт.

### 6.3 Манёвры от условий

- Шаги и ошибки манёвра получают `when` (условие на ключах `wind.side`, `place.*`, `wind.kn`).
- Набор шагов и правильный порядок зависят от обстановки.
- Пример для `mooring_med`:
  - при `wind.side in [port, starboard]` появляется шаг `windward_stern_first`, ошибка «подветренный первым» и шанс навалиться на соседа;
  - при `!place.marinero` появляется шаг `pick_lazy_line_boathook`;
  - при `place.seabed in [rock, weed]` у якорных манёвров появляется шаг `test_holding_astern`.
- Ошибки используют формат шансов §3.3. У подрульки (`bow_thruster`) есть `mods`.
- Порядок 3+ показывает подсказку: один шаг, добавленный обстановкой.
- Кнопка «как в прошлый раз» остаётся. Если в обстановке изменился набор шагов, она подставляет только совпадающие шаги и говорит об этом.

### 6.4 Новые типы манёвров

- `mooring_side_to` (лагом у набережной) и `anchor_stern_ashore` (якорь плюс кормовой на берег, тесные бухты).
- Точка объявляет доступные `berths`. Если их несколько (набережная: кормой или лагом), игрок выбирает в планировщике, и это тоже решение с разной ценой и риском.

### 6.5 События

- Добавляются поля `once` (по умолчанию `true`, совместимо), `cooldownDays` и `maxPerWeek`.
- События в пути бросаются **на каждом переходе** с ветром и признаками этого перехода (`leg.feature.*`), а не после дня по месту прибытия.
- Текстовые варианты: `text` может быть массивом, вариант выбирается по seed.
- Экипаж собирается из пула архетипов `core/crew.json` по seed. Имена в текстах подставляются плейсхолдерами `{crew.any}` и `{crew.role:sailor}`. Валидатор запрещает литеральные имена в текстах событий.

### 6.6 Критерии готовности 3c

- [ ] 4 шаблона погоды, направление ветра варьируется по дням. Укрытость бухт видна на карте.
- [ ] Карточка обстановки. Правильный порядок манёвра меняется от условий. Симулятор показывает, что за неделю встречается хотя бы 3 разных набора шагов для `mooring_med`.
- [ ] Два новых типа манёвров доступны в соответствующих точках.
- [ ] События в пути зависят от маршрута. Многоразовые события с кулдауном. Имена экипажа подставляются.

## 7. Сохранения, ошибки, тестирование

### 7.1 Сохранения

- Новый ключ `skipper.save.v2`. Сохранение `v1` не мигрируется. Меню сообщает «сохранение от старой версии несовместимо» и очищает слот.
- Схема сохранения валидирует `weather`, `dayFacts`, `expectations`, `systems`, `voiceXp` и `situation`: никаких `z.unknown()` (закрывает долг из stage2-followups).
- Внутри Stage 3 каждый план, который меняет `GameState`, поднимает внутреннюю версию схемы. Несовместимое сохранение обрабатывается тем же сообщением.

### 7.2 Ошибки

- Ошибки контента ловятся `validate` и тестами, не в рантайме. CI и деплой на Pages падают на них.
- Рантайм как раньше: `EngineError` с кодом, UI показывает локализованное сообщение по коду.

### 7.3 Детерминизм

Вся новая случайность идёт через seeded RNG движка: шаблон погоды, джиттер, дефекты, экипаж, маринеро, варианты текстов. Один seed даёт одну неделю при одинаковых решениях. На этом стоят тесты и симулятор.

### 7.4 Тесты

- **Движок, TDD:**
  - `evaluateChance`;
  - новые ключи условий;
  - опыт и рост уровня вечером;
  - системы (отказ, износ, ремонт, `brokenEffect`);
  - выбор дефектов;
  - `Situation`;
  - условные шаги и ошибки манёвра;
  - события с кулдауном и по переходам.
- **Контент:** тесты валидатора на каждый вид мёртвого контента. Контент района проходит `validate`.
- **Симулятор в CI** (100 недель, фиксированный набор seed) с порогами:
  - ни одно событие района не стоит на 0%;
  - слабость лодки ≥ 60% при `ignore-weakness`;
  - средний рост уровней 2–4 за неделю;
  - шанс хотя бы одной травмы за неделю в полосе, заданной в `balance.json` (порог в данных, а не в тесте).
- **UI:** обновлённые тесты экранов. Бот недели проходит RU и EN с ростом голоса, поломкой и ремонтом. e2e smoke на 375 и 1280 px.
- i18n-тест полноты строк распространяется на новый контент.

### 7.5 Порядок работы

1. План 3a: фундамент из §3 и голоса из §4.
2. План 3b: лодка, §5.
3. План 3c: разнообразие, §6.

Каждый план идёт в свою ветку и свой PR, после мержа Pages обновляется автоматически. Исполнение: subagent-driven, агенты ecc (`tdd-guide` при реализации, `typescript-reviewer` и `react-reviewer` на ревью задач, `architect` на финальном ревью).
